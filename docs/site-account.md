# Вход на сайт через Telegram

В личном чате владелец открывает `/site` или **Аккаунт сайта**, нажимает **Войти**, присылает почту и пароль. При запросе сайта бот попросит код из письма. Есть статус, повторный вход, отмена и удаление сохранённого входа с сервера. Доступ проверяется по `TELEGRAM_CHAT_ID`: это должен быть личный числовой ID владельца, не ID группы. Сначала требуется обычная авторизация в боте.

Пароль и код живут только в памяти текущей попытки. Сообщения с почтой, паролем и кодом удаляются по возможности; Telegram не гарантирует их полное удаление со всех устройств и не обеспечивает сквозное шифрование переписки с ботом. Сессия содержит секретные cookies/tokens: защищайте файл и резервные копии так же, как пароль. На POSIX используются права 0700/0600; на Windows необходимо ограничить доступ к папке средствами ACL.

## Настройки

- `SITE_LOGIN_URL`: необязательная HTTPS-ссылка страницы сайта, на которой доступна форма входа. По умолчанию `GAME_URL`. Если `GAME_URL` ведёт прямо на провайдера игры, укажите страницу входа самого сайта в `SITE_LOGIN_URL`.
- `SITE_SESSION_PATH`: по умолчанию `data/site-auth/session.json`. Сохраняйте папку `data` на постоянном Docker volume и включите файл сессии в защищённую резервную копию. Файл привязан к origin страницы входа; смена зеркала требует нового входа.
- `SITE_AUTH_EMAIL_SELECTOR`, `SITE_AUTH_PASSWORD_SELECTOR`, `SITE_AUTH_CODE_SELECTOR`: CSS-селекторы полей. По умолчанию используются стандартные типы и имена email/password/code и `autocomplete=one-time-code`.
- `SITE_AUTH_SUBMIT_SELECTOR`, `SITE_AUTH_CODE_SUBMIT_SELECTOR`: CSS-селекторы кнопок отправки при нестандартной разметке.
- `SITE_AUTH_SUCCESS_SELECTOR`: CSS-селектор элемента, доступного **только после входа**. Не используйте общедоступные баланс/историю/коэффициенты, кнопки регистрации или исчезновение окна входа. Есть резервный поиск видимой надписи «Выйти»/«Выход»/«Log out»/«Sign out».
- `SITE_AUTH_ERROR_SELECTOR`: CSS-селектор ошибки, по умолчанию `[role=alert], [data-testid=login-error]`.

Кнопка входа, вкладка «Почта», стандартные email/password и кнопка «Войти» поддержаны. Для неизвестной DOM-разметки нужны точные селекторы. Скриншот формы не подтверждает её DOM и не позволяет проверить конкретный сайт.

## Поведение

Ввод ограничен тремя минутами на поле, вся попытка — десятью минутами. Код: 4–10 цифр, до трёх попыток. CAPTCHA не обходится. При неожиданном переходе на другой origin бот не вводит секреты и сообщает об ошибке. Успех требует явного элемента аккаунта/выхода.

Пароль не сохраняется, поэтому после истечения сессии потребуется повторить вход через Telegram. Файл сессии сам по себе не доказывает, что сервер сайта всё ещё принимает её; статус после перезапуска честно сообщает «Сессия сохранена». Удаление сессии на сервере не отзывает другие сеансы аккаунта на сайте.

Монитор и вход используют один browser lock. После успешного входа или удаления сессии монитор открывает новый browser context с актуальным состоянием. Пока выполняется вход, браузер мониторинга освобождается; возможна пауза получения раундов. Существующий обработчик разрывов истории остаётся включённым. Вход не выполняет ставок и не меняет пользовательские балансы/историю.

## Проверки перед включением

1. Установить зависимости проекта и Chromium; выполнить `PYTHONPATH=src:. pytest -q`.
2. Проверить, что `TELEGRAM_CHAT_ID` принадлежит владельцу и правильна ссылка `SITE_LOGIN_URL`.
3. Запустить с постоянным хранилищем `data`.
4. В Telegram пройти вход самим владельцем и проверить код из письма.
5. Проверить положительный маркер входа, повторный запуск с сессией, отмену и удаление сессии.

Автоматизированные проверки включают настоящий Chromium с перехватом HTTPS-запросов на локальную тестовую форму: email/password, неверный и верный OTP, сохранение localStorage и отказ признавать исчезновение формы успешным входом. Настоящий сайт и аккаунт владельца этими проверками не охвачены.

Хранение и повторное использование browser storage: https://playwright.dev/python/docs/auth
